## 一、术语表

以下词汇在本项目中**只有一个含义**。新增同义词必须走术语表变更流程。

### 1. 对象层

| 术语 | 定义 | 举例 | 反例（不是这个） |
|---|---|---|---|
| **术数体系** System | 一套具备自身推演程式的完整体系。**一个 System 可以引用一个或多个形式系统**（如七政四余同时使用十二地支与七政） | 塔罗、六爻、梅花易数、占星、七政四余 | 「占卜」不是体系，是用途 |
| **形式系统** Formalism | 一套**符号集与符号间规则**；判据是「符号集是同一套，且符号间规则可互相定义」，**不是文化圈**（ADR-0009）。`Symbol` 归属于 Formalism，`System` 通过「用法」引用它 | 东方象数（阴阳·五行·干支·八卦）、希腊四元素、行星黄道、塔罗象征系统 | 「东方术数」不是 Formalism，是一个文化范围 |
| **符号用法** SymbolUsage | 「某个体系以什么角色使用某个符号」的连接（含体系与流派） | 六爻以「卦宫五行」角色使用「五行.木」 | 符号本身不是用法 |
| **流派 / 传承** School | 体系内部的解释与实践分支，对同一符号或规则可有不同处理。**必须以「可引证文献」为锚，不得以「古法/新派」这类无学术界定的当代实务分类为锚**（ADR-0012） | 依据《增删卜易》一路的取法；依据《卜筮正宗》的取法 | 「塔罗」不是流派，是体系；「现代新派」不得作锚 |
| **符号** Symbol | 形式系统内可被直接指认的最小离散单元。**属性空间的取值也是符号**（ADR-0010），因为它们要被规则作用、要携带来源与流派、要参与有向关系 | 圣杯六、地天泰、火星、甲子、乾卦、**水、火、阴、阳** | 「相生」是关系，不是符号 |
| **属性空间** AttributeSpace | 一组可用来给符号分类的维度。**其取值是符号**（ADR-0010） | 五行、四元素、阴阳、极性、数字 | — |
| **属性归属** has_attribute | 「某符号在某属性空间中取某值」的赋值关系 | 甲 →(五行) 木 | 不是实体，是关系。V0.1 原「`Attribute` 实体」已废止（ADR-0010） |
| **概念** Concept | 跨符号、可复用的抽象认知单元，是**学习的真正对象** | 变化、体用、旺衰、相位、时间性、主客 | 「愚人」是符号，不是概念 |
| **认知图式** Schema | 一组概念构成的、可复用的**认知操作模式**，是跨体系迁移的挂载点（V0.1 待验证假设） | 指认、归类、对立配对、作用联结、组合成局、演化、取舍判断、叙事、**取象/命题（S9，ADR-0015①）** | — |
| **关系** Relation | 两个及以上**符号**之间的有类型连接 | 生、克、冲、合、相位、互卦、牌序、宫主 | 「都是水」是共同属性，不是关系 |
| **规则** Rule | 从符号与关系推导出判断的**确定性程序** | 六爻装卦纳甲、月建旺衰判定、牌阵位置约束 | 「我感觉」不是规则 |
| **判断** Judgment | 依规则与结构得出的结论陈述 | 「此卦用神受克，事难成」 | 判断的**准确率**不是产品的考核对象 |

### 2. 学习层

| 术语 | 定义 | 关键澄清 |
|---|---|---|
| **技能** Skill | 用户的一种**可练习、可评估**的能力 | Skill **不是** Concept 的子节点。一个 Skill 依赖 N 个 Concept 与若干 Rule（例：「判断用神旺衰」依赖 用神/五行/月建/日辰/生克） |
| **技能图** SkillGraph | 技能之间的前置依赖 DAG | 不是课程顺序；课程顺序是它的一个线性化 |
| **单元** Unit | 教学编排容器，目标是让用户习得一组 Skill | 存在于「教学层」，与知识层解耦 |
| **关卡** Lesson | 单元内的最小教学段 | — |
| **练习** Exercise | 一次评估活动 | 一个 Exercise 可同时测多个 Skill |
| **判分规约** Rubric | 对一个 Exercise 的评分标准：必需要素 / 加分要素 / 禁止推断 / 容许流派差异 / 过程规范 | **全项目最关键的教学资产**，见 V0.1 第 7 节 |

### 3. 用户状态层

| 术语 | 定义 | 关键澄清 |
|---|---|---|
| **掌握度** Mastery | 用户对某 Skill 的**多维能力向量**，不是单一百分比 | 见 V0.1 第 6 节 |
| **证据** Evidence | 一次练习产生的、可用于更新掌握度的观测记录 | 含正确性、提示使用、耗时的**原始事件**，非结论 |
| **混淆对** ConfusionPair | 用户**系统性**把 A 判断为 B 的错误模式 | 比正确率有价值得多：它直接给出复习靶点 |
| **复习项** ReviewItem | 由掌握度衰减与混淆对共同排程的复习任务 | 不是「错题本」的简单翻版 |
| **迁移** Transfer | 已有认知结构对新体系学习的助益 | 强度**不等**于体系相似度，须按类型学标注 |

### 4. 迁移与证据层

| 术语 | 定义 |
|---|---|
| **迁移类型** TransferType | 跨体系关系边的类型。**ADR-0009/0011 后只有三类**：历史影响 / 功能类比 / 修辞比喻。V0.1 原有的「同源同构」「共享形式系统」**不再是迁移类型**——它们由 `Formalism` + `SymbolUsage` 自动推导，不落库为边（ADR-0011） |
| **派生投影** same_formalism_projection | 同一 `Formalism` 内的符号被不同体系以不同规则使用的对应关系。**自动推导，不人工建边**（ADR-0011） |
| **体系投影** Projection | 同一概念/符号在不同体系中的具体化用法（`projects_to`） |
| **来源** Provenance | 每条知识条目的出处，含文献与可核查链接 |
| **来源强度** SourceStrength | 高 / 中 / 低，决定该条目能否作为练习考点。**原名「证据强度」，因与用户状态层的「证据」同词冲突而改名**（ADR-0015⑥，认识论原则 7） |
| **争议标记** ControversyFlag | 标记该条目在流派或学界存在分歧，UI 必须显式呈现 |
| **审核状态** ReviewStatus | `draft` → `reviewed` → `deprecated`；**只有 reviewed 可上线** |

## 二、认识论原则（产品级铁律）

违反以下任一条的内容或功能，**不得上线**。

1. **体系主张 ≠ 产品裁定。** 产品不裁定哪个流派正确，只标注差异。遇到分歧，同时呈现，并说明分歧点。
2. **跨体系关系边必须双标注。** 每条边必须声明 `迁移类型` + `来源强度`；缺任一项，构建失败。（原名「证据强度」，见术语表 — ADR-0015⑥）
3. **无来源，不入库。** 未标注来源的术数理论不得进入内容库。AI 只能产出 `draft` 候选，AI 产出**永远不能**直接进入 `reviewed`。
4. **争议不得伪装成定论。** 存在学术或流派争议处，必须以不确定语气呈现，并给出分歧双方。
5. **类比必须可见。** 教学类比不得伪装成理论等价；UI 上类比必须被用户看见（不是埋在脚注）。
6. **实战考过程，不考准不准。** 实战能力的评估对象是**过程规范性与解读完整性**。产品不承诺、不呈现、不暗示预测准确率。（对应 ADR-0004）
7. **术语唯一性。** 同一词在全产品只有一个含义；数据库字段名与技术术语不得与业务术语冲突。
8. **可证伪优先。** 训练用户给出「可被后续事实检验」的判断陈述（含时间节点与可观察事件），而不是含糊其辞的万能话术。

## 三、非目标清单（第一版明确不做）

> 写清楚"不做什么"比写清楚"做什么"更能防止项目失控。

**产品形态**
- ❌ 不做 AI 占卜 / 预测结果生成器（AI 不预测，课程可以教怎么判断）
- ❌ 不做算命社区、大师交易、付费咨询撮合
- ❌ 不做"体系等价对应表"（东西方一一映射）
- ❌ 不做排行榜、社交动态、好友 PK（第一版）

**内容**
- ❌ 不允许 AI 生成并直接发布的术数理论内容
- ❌ 不做八字、紫微斗数、奇门遁甲的**课程内容**（知识图谱可留占位节点，内容不做）
- ❌ 不把某一流派观点包装为"术数界的共识"
- ❌ 不做未标注的跨体系对应

**技术**
- ❌ 不做完整排盘/装卦引擎（进入六爻/占星课程时以**规则引擎**实现，**绝不允许 AI 推算**）
- ❌ 不为了"AI"而做全站 RAG（先做小规模可人工维护的知识库 + 规则引擎）
- ❌ 不引入图数据库（PostgreSQL 邻接表 + 递归 CTE 足够用很久）
- ❌ 不做微服务、不做多端原生 App

**考核**
- ❌ 不以"预测准确率"作为任何功能的卖点或指标
- ❌ 不以刷 XP 为目的设计大量简单选择题（游戏化必须服务于学习）

## 四、伦理与法律边界（scope C 必需）

既然产品要教到「能对他人实战断事」，必须把伦理做成**产品内容的一部分**，而不是免责声明里的一行字。

1. **能力免责**：产品定位为学习工具，解读输出不构成医疗、法律、财务、心理或其他专业建议。
2. **面向他人的伦理准则必须是课程内容**，且是**必修关卡**，不能是可选阅读。建议覆盖：
   - 告知与同意：必须让对方知道你在做什么、依据什么体系
   - 不涉重大决策：不得替代就医、诉讼、投资、婚姻等重大决策
   - 红线识别：出现自伤、家暴、急性精神症状等信号时，必须中止"解读"并引导求助
   - 不制造恐惧依赖：禁止用"灾祸/必应"式表述建立依赖
   - 隐私：对方信息的保存与不外传
3. **过程留痕**：实战类练习要求用户写下问题界定、假设声明、流派声明、判断与时间节点——这既是教学手段，也是"我提供了过程而非承诺"的证明。
4. **不提供确定性话术模板**：如果课程教用户对他人说"一定会发生"，那是产品在制造伤害。判分规约中此类表述应进入 `forbidden`。
