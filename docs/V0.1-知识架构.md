## §1 核心学习单位是什么

**答案分三层，必须分开——这是整个架构的第一块基石。**

| 层 | 单位 | 回答 | 例 |
|---|---|---|---|
| 认知单位 | **Concept**（原子概念）+ **Schema**（认知图式） | "用户脑子里多了一个什么结构" | 「变化」「体用」「旺衰」 |
| 可评估单位 | **Skill** | "用户现在能做什么" | 「能判断用神是否受月建生扶」 |
| 交互单位 | **Exercise** | "用户刚才做了什么动作" | 拖动三张牌排序并写出叙事 |

**为什么必须分开：** 这三者是**多对多**关系。一个 Skill 依赖多个 Concept；一个 Exercise 可测多个 Skill；一个 Concept 出现在几十个 Lesson 里。若按一条链（Concept → Skill → Lesson → Exercise → Mastery）建模型，第二天就会发现"这个 Concept 属于哪个 Skill"无法回答——因为答案是"很多个"。

**产品真正的复利资产是两样东西：**
1. **Concept ↔ Relation 图**（知识层）：加第二门体系时只是加投影，不是重写引擎。
2. **Rubric 库**（教学层）：判分规约是唯一能表达"术数解读没有唯一正确答案"的结构，也是 AI 反馈的质量上限所在。

**不是资产的：** 页面、动画、XP 数值、牌面图片。这些可以随时换。

## §2 统一抽象：四层图模型

```
Layer 0  元数据层（横切所有层）
         Provenance · SourceStrength · ControversyFlag · ReviewStatus
         ↑ 每个知识层实体都必须携带；缺失即不可上线
         （原名 EvidenceStrength，因与 Layer 4 的 Evidence 同词冲突已改名 — ADR-0015⑥）

Layer 1  知识本体层   世界上存在什么
         Formalism · System · School · Symbol · SymbolUsage · AttributeSpace
         · Concept · Schema · Relation · Rule · RuleTestSet

Layer 2  能力层       用户能做什么
         Skill · SkillEdge(prerequisite)

Layer 3  教学层       怎么教、怎么测
         Path · Unit · Lesson · Exercise · AssessmentSpec · Rubric

Layer 4  用户状态层   用户现在会什么
         User · UserConceptState · UserSkillMastery · ConfusionPair
         · ReviewItem · Attempt · Evidence
```

**分层的硬约束：**

- Layer 1 不含任何教学信息。"先学愚人再学魔术师"是教学决策，不是知识属性。
- Layer 2 不含任何顺序。SkillGraph 是 DAG，课程顺序只是它的一个线性化；同一 DAG 可以排成不同 Path。
- Layer 2 **不含任何 Rubric 指针**。"这个 Skill 必须用哪份判分规约"属于 Layer 3（`AssessmentSpec`）——见 ADR-0015⑤。
- Layer 3 可以被整体替换（换一套课程设计、换一种题型）而不动 Layer 1/2。
- Layer 4 只由 Evidence 驱动，不由"完成度"驱动（看完了 ≠ 会了）。

### Layer 1 实体（骨架）

> **本节已按 ADR-0009–0013 修订。** 关键变化：新增 `Formalism`（符号归属从 `System` 改为 `Formalism`）、新增 `SymbolUsage`、**新增 `AttributeSpace` 并废止 `Attribute` 实体**、`System` 去掉 `family`、`School` 增加 `anchor_sources[]`。

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **Formalism** | name, description, symbol_scope | **形式系统**。判据 = 「符号集是同一套，且符号间规则可互相定义」，**不是文化圈**（ADR-0009）。清单 4 个：①东方象数（阴阳·五行·干支·八卦）②希腊四元素 ③行星黄道（占星）④塔罗象征系统 |
| System | name, era, default_school_id | 体系。**不含 `family`**——七政四余同时引用「东方象数」与「行星黄道」两个 Formalism，二值字段无法容纳（ADR-0015④）。传统归属由 `SymbolUsage` 推导 |
| School | system_id, name, stance, **anchor_sources[]** | 流派。**必须以「可引证文献」为锚**（如"依据《增删卜易》一路的取法"），**不得用「古法/新派」这类无学术界定的当代实务分类作锚**（ADR-0012）；**年份字段可空且不得编造**。`contradicts` 可跨 School 连接 |
| Symbol | **formalism_id**, canonical_name, aliases[] | 符号。归属于 `Formalism`，不再归属 `System`。"六爻的乾"与"梅花的乾"**是同一个 Symbol 节点**（同一 Formalism），由 `SymbolUsage` 区分用法。**属性空间的取值（水、火、阴、阳）也是 Symbol**（ADR-0010） |
| **SymbolUsage** | symbol_id, system_id, school_id, role | 「某体系以什么角色使用某符号」。一个 System 可引用**多个 Formalism** 的符号 → 这是跨 Formalism 体系的表达方式 |
| **AttributeSpace** | name, formalism_id | 属性空间：五行 / 四元素 / 阴阳 / 极性 / 数字。**代表 `Attribute` 实体**（ADR-0010） |
| **has_attribute** | symbol_id, space_id, value_symbol_id | 属性归属**关系**（不是实体）。"甲属木" = `has_attribute(甲, 五行, 木)` |
| Concept | name, definition, schema_id? | **体系无关**，是跨体系挂载点 |
| Schema | name, description | 认知操作模式，见 §4。**S1–S9**（S9 取象/命题，ADR-0015①） |
| Relation | from, to, type, direction, school_id? | 生 / 克 / 冲 / 合 / 相位 / 互卦 / 牌序。**两端都是 `Symbol`**——这正是 M13 修订的理由（ADR-0010） |
| Rule | system_id, school_id, procedure_ref, test_set_id, sources[] | 确定性程序，由**规则引擎**执行，AI 不得介入 |
| **RuleTestSet** | rule_id, cases[{input, expected}] | 规则验证集。规则引擎正确性的唯一保证（M6） |

### 关系类型清单（关键设计）

| 关系 | 方向 | 用途 |
|---|---|---|
| `has_attribute` | Symbol → Symbol（取值） | 属性归属（取代原 `attribute_of`） |
| `related_by` | Symbol ↔ Symbol | 体系内关系（生克冲合相位） |
| `used_as` | Symbol → (System, role) | 符号用法（`SymbolUsage`） |
| `variant_of` | School → School | 流派变体 |
| `contradicts` | 任意 ↔ 任意 | 流派/学界冲突，UI 必须呈现 |
| `projects_to` | Concept → (System, Rule) | **体系投影**（§3） |
| `transfers_as` | Concept/Schema/Symbol ↔ 同类节点 | **跨体系迁移边**（§5）。**只有类型 3/4/5**（ADR-0011） |
| `prerequisite_of` | Skill → Skill | 能力依赖 |
| `teaches` / `assesses` / `requires` | Lesson/Exercise → Skill；Skill → Concept | 教学与能力连接 |
| `confusable_with` | Symbol/Concept ↔ Symbol/Concept | **内容侧预设易混淆对**（见 §9.3，这是关键设计） |
| `supported_by` | 任意 → Provenance | 证据支撑 |

### 派生视图（不落库）

| 视图 | 定义 | 为什么不是边 |
|---|---|---|
| `same_formalism_projection` | 同一 `Formalism` 内的符号被不同体系以不同 `Rule` 使用的对应关系 | **可自动推导**（查 `SymbolUsage` + `Rule` 即可），人工建边会产生 O(n²) 冗余并与推导结果不一致（ADR-0011）。这对应 V0.1 §3 的「机制 A」 |

## §3 统一抽象是否成立：成立，但必须是"两个机制"，不是一个

**这是本文档最重要的结论。**

四类体系可以统一抽象，但**东方内部**与**东西方之间**的跨体系关系在数据结构上完全不同，**绝不能混在一个功能里**。

### 机制 A：共享形式系统（东方内部）

六爻 / 梅花易数 / 八字 / 紫微斗数 / 奇门遁甲 共享**同一套底层符号系统**：阴阳、五行、天干地支、八卦、生克冲合。

> 这不是"类比"，是**同一形式系统在不同用途下的投影**。

**数据结构：** 复用**同一批 Symbol / Concept 节点**（它们归属同一个 `Formalism`），各体系通过不同的 `Rule` 与 `SymbolUsage` 来使用它。

```
Formalism: 东方象数
     └─ belongs_to ── Symbol: 乾 · 甲 · 木（五行取值）
              ↑ SymbolUsage(system=六爻, school=…, role=卦宫五行)
              ↑ SymbolUsage(system=梅花, school=…, role=体用)
              ↑ SymbolUsage(system=八字, school=…, role=日主强弱)
```

> **ADR-0011 的重要后果：** 机制 A **不产生 `transfers_as` 边**。它是从 `Formalism` + `SymbolUsage` + `Rule` **自动推导**的派生视图 `same_formalism_projection`。原 V0.1 把「同源同构 / 共享形式系统」列为迁移类型 1/2，会导致枚举里有两个永远取不到的值（见 §5.1 修订）。

**结果：** 东方体系之间的"跨体系学习"**几乎免费**——用户已经掌握的 Concept 节点直接复用，只需学习新的 Rule。学习成本 ≈ 只学生疏的那部分规则。可信度**高**（这是同一套理论）。

**这是跨体系功能的第一个交付目标**：成本低、学术上站得住、且能立刻验证"迁移"这个机制是否真的有效。

### 机制 B：迁移类比（东西方之间，以及塔罗↔占星）

塔罗 / 占星 与 东方术数之间**不存在共同形式系统**（跨 Formalism）。它们之间只能建立 `transfers_as` 边，且**每条边必须携带迁移类型 + 来源强度**。

**结果：** 学习成本**不低**（用户需要建立新结构，只是借用旧结构的"形状"来理解），可信度取决于类型，**必须显式标注**。

### 塔罗 ↔ 占星 是第三种情况

二者同属西方秘教传统，存在**有文献记载的对应关系**（Golden Dawn 等将行星/星座指派到牌）。

> **✅ 已核实并定案（原「待核实」已解除）。** R1 给出可查文献链：Eliphas Lévi（1856）将 22 张大牌对应 22 个希伯来字母 → Golden Dawn（1888 起）Mathers 编 *Book T*，把 36 decans 分派给四花色 2–10，并给大牌行星／星座（置信度中–高）。同时 Dummett & Decker 学派主张秘教／占星含义是 18–20 世纪重构（置信度**高**）。
>
> 因此按 **ADR-0009 + ADR-0014** 落地：「行星」「星座」归属 **③行星黄道 Formalism**；塔罗对它们的引用是**跨 Formalism 的 `transfers_as` 边，类型 3 历史影响，`historicity = 重建`**——**不是共享符号**，**也不是塔罗与占星同源**。这条边就是 MVP 的跨体系节点。
>
> **反面（必须避免）：** 若把「行星」同时放进一个笼统的「西方秘教 Formalism」，塔罗的火星就会变成占星的共享符号，等于用数据结构断言同源——这正是 V0.1 §5.4 要防的附会。ADR-0009 的 4 项 Formalism 清单就是为堵这个洞而设。

### 结论

> **统一抽象成立的前提是：把"同源体系的投影复用"与"异源体系的迁移类比"拆成两个机制。** 混成一个，会同时做坏两个——前者被过度标注而显得可疑，后者被过度简化而变成附会。

## §4 概念层与图式层（迁移的挂载点）

### 问题

Concept 如果只到"变化""关系"这种抽象度，会**不可教也不可测**；如果细到"月建生扶用神"，又**无法跨体系**。

### 提案：两层概念节点

| 层 | 抽象度 | 例 | 可测？ |
|---|---|---|---|
| **Concept**（原子概念） | 中，体系无关 | 相生、旺衰、宫位、极性、主客 | ✅ 可出题 |
| **Schema**（认知图式） | 高，可复用的**操作模式** | 指认 / 归类 / 对立配对 / 作用联结 / 组合成局 / 演化 / 取舍判断 / 叙事 | ✅ 可出题（考操作） |

**跨体系迁移边主要挂在 Schema 上**，而不是挂在原子 Concept 上。理由：迁移发生的是**认知操作方式的复用**，不是词汇的翻译——用户学六爻时习得的是"从一组符号的作用关系里提取一个动态结论"这个**操作**，这个操作在塔罗里同样要用。

> ⚠️ **这是待验证假设，不是定论。** 验证方式见 §7 的"第二门体系压力测试"。若 Schema 层在 V0.2 中无法产生可测题型，则删掉该层，退回纯 Concept 图。

### 基础层：从 12 个元概念收敛为图式（V0.2 后为 9 个）

brief 提出的基础层 12 项（象、数、分类、属性、结构、关系、变化、时间、空间、组合、判断、叙事）**方向正确，但作为课程单元不可用**——它们是"学科视角"而非"可教可测的单元"，直接做成课程会变成哲学课，用户学完仍然不会看牌。

**建议收敛为 Schema，每个都绑定可出题的操作：**

| # | Schema | 操作定义（用户能做什么） | 覆盖的元概念 |
|---|---|---|---|
| S1 | **指认** | 从一个符号系统里准确找出/命名一个符号 | 象 |
| S2 | **归类** | 按属性把符号分组，并说出依据 | 分类、属性、数 |
| S3 | **对立配对** | 找出/构造成对的对立或互补关系 | 关系（二元）、阴阳 |
| S4 | **作用联结** | 判断两个符号之间的**有向作用**（生/克/相位/顺序） | 关系（有向） |
| S5 | **组合成局** | 把多个符号读成一个**结构**（卦/牌阵/星盘） | 结构、组合、空间 |
| S6 | **演化** | 判断结构在时间/条件变化下如何转移 | 变化、时间 |
| S7 | **取舍判断** | 从结构中提取一个结论，并说明依据与权重 | 判断 |
| S8 | **叙事** | 把判断组织成他人可理解的说明，并区分"所示"与"推测" | 叙事 |
| **S9** | **取象 / 命题** | **把现实问题映射为可判断的符号对象，并说明映射依据** | 象（入口方向） |

**"数"与"时间/空间"为何不单列：** 它们是**属性维度**（数字、时间戳、宫位/方位），归入 S2 与 S5/S6 即可。单列会让基础层虚胖。

> **S9 的来历（V0.2 §5.4）：** V0.2 用六爻压测时发现，上述 8 个图式**都在描述符号系统内部的操作**，但任何一次真实解读的第一步是**把现实问题映射到符号**（六爻取用神、梅花起卦取数、塔罗选牌阵与界定问题、占星问事宫位）。该操作不属于任何现有图式、流派分歧显著（用神取法）、是初学者最大的失败点，也是实战能力的核心。
>
> **✅ 定案（ADR-0015①）：收敛为 9 个（S1–S9）。** 且 S9 在教学中应**提前**（它是入口技能，不是高阶技能），并在 B2 流派对比课程里**再次出现**（同一卦例、两派取用神不同、结论不同）。

## §5 迁移类型学

> ⚠️ **本节已按 ADR-0011 重构。** 原五类中的「类型 1 同源同构」「类型 2 共享形式系统」**不再是迁移类型**——它们在 ADR-0009 引入 `Formalism` 层之后变成**可自动推导的派生关系**（`same_formalism_projection`），不落库为边。把它们留在枚举里会产生两个永远取不到的值，并使「机制 A 免费」的结论失效。
>
> **判据（ADR-0009）：**
> - 同一个 `Formalism` 内 → **机制 A**，共享节点 + 自动推导，**不建边**
> - 跨 `Formalism` → **机制 B**，必须建 `transfers_as` 边 + 类型 + 证据

### §5.1 三类迁移及其准入（ADR-0011 后的唯一定义）

| 类型 | 定义 | 判据 | 例 | 允许的表述 | 禁止的表述 |
|---|---|---|---|---|---|
| **3 历史影响** | 有可查证的传播/借用关系 | 有文献证据的传播路径 **+ 必须声明 `historicity`** | **塔罗 ← 占星的行星/星座指派**（Lévi 1856 → Golden Dawn *Book T* 1888，`historicity = 重建`，置信度中–高）<br>**七政四余 ← 印度/希腊占星**（唐《都利聿斯经》《符天历》、8 世纪不空译《宿曜经》，`historicity = 传播`，置信度**高**） | 按 `historicity` 分级表述 | 「塔罗本来就是占星」 |
| **4 功能类比** | 结构/功能相似，来源**无关** | 结构可映射，无共同祖先 | 六爻动爻 ↔ 塔罗牌组演化 | "这是**教学类比**，不是理论等价" | 任何暗示理论同源的表述 |
| **5 修辞比喻** | 仅语言层面相似 | — | "塔罗的'水'像五行的'水'" | **不进教学内容** | 作为学习目标或考点 |

### §5.1b 已废止的类型（保留记录，避免重新引入）

| 原类型 | 原定义 | 现状 | 为什么废止 |
|---|---|---|---|
| ~~1 同源同构~~ | 同一形式系统，符号相同，用法可对应 | **改为派生视图** `same_formalism_projection` | 六爻↔梅花的八卦/五行是**同一个 `Symbol` 节点的两种 `SymbolUsage`**，查询即可得到，人工建边是冗余 |
| ~~2 共享形式系统~~ | 共享底层符号，但推演规则不同 | **同上** | 六爻↔八字的干支同理：符号同源、`Rule` 分岔，是投影不是边 |

> **这两类不是被否定，而是被「降级为可推导」。** 它们的教学含义完全保留（这正是机制 A「跨体系学习几乎免费」的结论来源），只是不再需要人工维护数据。
>
> **V0.1 原有的表述（"这是同一个东西" / "底层符号相同，用法不同"）仍然有效**，作为派生视图的**文案模板**继续使用。

### §5.2 准入规则

每条 `transfers_as` 边必须携带：

```
from, to,
transfer_type ∈ {3 历史影响, 4 功能类比, 5 修辞比喻}   // ADR-0011：只有三个值
historicity?          // 类型 3 必填：传播 / 重建 / 不明
source_strength       // 高/中/低（原名 evidence_strength — ADR-0015⑥）
sources[], reviewer, review_status
paired_reverse_exercise_id?   // 类型 4 必填
```

- **来源强度 = 低** 的边：只能出现在"延伸阅读"，**不得作为练习考点**，不得进入技能树前置。
- **类型 4/5** 的边：UI 必须显示"类比"徽标，且必须在文字中被明确称为类比。
- 任何边缺失 `transfer_type` 或 `sources` → **CI 构建失败**（认识论原则 2）。
- **ADR-0007 已定：类型 4/5 的边允许进入产品**，但必须满足三条硬约束：①UI 可见的「类比」标注 ②四段式结构（§8.2）③**必须配反向练习题**。第三条是 CI 校验规则——类型 4 的边若无配对反向练习，构建失败。**同步适用于类型 3 的 `historicity = 重建` 边**（ADR-0014：重建类对应同样要找出指派的可争议处，见 §8.2 第 ④ 段）。
- **类型 1/2 不在此列**——它们不是边（ADR-0011）。CI 不再对它们做任何校验，因为不存在需要校验的条目。


#### §5.2.1 类型 3 必须再分 `historicity`（研究证据 R1 带来的修订）

「有历史影响」有两种完全相反的情况，**教法完全不同，不能共用一套表述**：

| `historicity` | 含义 | 例 | 教学表述 |
|---|---|---|---|
| **传播** | 真实的历史传播/借用 | 七政四余 ← 印度/希腊占星（置信度高） | "这套体系的这部分**源自那里**" |
| **重建** | 有据可查的**近代建构** | **塔罗 ← 占星的行星/星座指派**：Lévi 1856 → Golden Dawn *Book T* 1888（置信度中–高；Dummett & Decker 学派主张整个秘教/占星含义是 18–20 世纪重构，置信度高）——**这是 MVP 的跨体系节点（ADR-0014）** | "这是 **19 世纪某人建构出来的**，不是塔罗原生理论" |
| 不明 | 有传播迹象但证据不足 | — | 只能进延伸阅读 |

> **`historicity = 重建` 不是坏消息，反而是更好的教学素材。** 它让产品可以教"秘教体系是如何被建构出来的"——这是同类产品不会讲的诚实话，也是本产品"认识论诚实"定位的直接兑现。
>
> **ADR-0014 补充：`重建` 类的边还有一项现成的反向练习素材。** R1 Q1.6 记载 **RWS 把力量（狮子座）置于 VIII、正义（天秤座）置于 XI，与 Golden Dawn 原序（VIII＝正义／天秤）相反**，托特则沿用原序。这是「人类手工指派可以怎样任意漂移」的**可查证实例**，比自造的类比失效场景强得多。即：重建类对应的第 ④ 段反向练习 = 「指出这个指派被人改过、且改动无理论依据」。

>
> 塔罗↔占星按 `historicity = 重建` 处理：**可以进考点**（因为它有确凿的文献链条），但表述必须是"Golden Dawn 的建构"，绝不能是"塔罗与占星本相通"。

#### §5.2.2 三档准入（研究证据 R1 带来的修订）

V0.1 原先只有"允许/禁止"两档，太粗。研究暴露出一条中间地带，也暴露出一类比"有争议"更糟的情况：

| 档 | 判据 | 处理 | 例 |
|---|---|---|---|
| **档 1 可考点** | 有可靠来源的历史关联（**类型 3**）或同一 Formalism 内的派生投影 | 可作考点，标 `historicity` | 七政四余←印度占星；塔罗←占星的行星指派；东方内部共享符号（派生视图，不需建边） |
| **档 2 类比考点** | 结构相似、来源无关（**类型 4**） | 可作考点，标"类比" + 反向练习 | 六爻动爻 ↔ 塔罗牌组演化 |
| **档 3 禁止入库** | **找不到任何可引证来源** | **禁止进入内容库**（比"标注为类比"严格得多） | 六亲↔宫廷牌、十神↔相位（R1：未找到任何学术或可靠文献） |

> **档 3 是这次研究最重要的收获。** 原先 §5.4 把"六亲↔宫廷牌"写成"标为类比即可"，但 R1 显示**这类对应连一条可引证的来源都没有**。按认识论原则 3（无来源不入库），它们不是"需要标注的类比"，而是**根本不该出现的附会**。二者性质不同，必须分开。

### §5.3 可迁移的概念候选

> **表中「东方内部」一列的取值已按 ADR-0011 改写：** 不再写"1/2"，因为它们不是迁移类型，而是 **派生投影（自动推导）**。

| 图式 | 六爻 | 梅花易数 | 塔罗 | 占星 | 关系判定 |
|---|---|---|---|---|---|
| S4 作用联结 | 生克冲合 | 体用生克 | 牌与牌的支持/削弱（若牌阵定义） | 相位 | 东方内部：**派生投影**；东西之间：**类型 4 边** |
| S6 演化 | 动爻→变卦 | 体用随互变卦转移 | 牌组的时间/因果展开 | 行运/推运 | 东方内部：**派生投影**；东西之间：**类型 4 边** |
| S3 对立配对 | 阴阳、世应 | 体用 | 正逆位、对宫牌 | 对宫星座、对冲相位 | 东方内部：**派生投影**；跨东西：**类型 4 边** |
| S5 组合成局 | 六爻成卦 | 本卦/互卦/变卦 | 牌阵 | 星盘 | 跨东西：**类型 4 边**（结构类比） |
| S7 取舍判断 | 用神旺衰取用 | 体用强弱 | 牌阵位置权重 | 主要相位与宫主 | 东方内部：**派生投影** |
| S1/S2 指认归类 | 八卦属性 | 八卦属性 | 牌义与**元素**（共享 ②） | 行星/星座属性、**元素**（共享 ②） | 东方内部：**派生投影**；**元素：塔罗↔占星共享（机制 A）**；**行星/星座：类型 3 边**（`historicity=重建`，ADR-0014） |

> **注意：** 上表中所有"东西之间"的关系，要么是**同 Formalism 内可自动推导的投影**，要么是**类型 4 功能类比**。这不是保守，这是事实陈述。把它们当成"同源"或"共享形式系统"，就是伪造理论。
>
> **塔罗↔占星的单列：** 它是上表里唯一一条**类型 3** 的边（`historicity = 重建`），不能与「东西之间 = 类型 4」这个概括混为一谈——因为塔罗与占星**同属西方秘教传统且指派有文献链**，而东西之间**没有任何传播证据**。这是三条不同性质的关系，UI 与教材必须分开表述（ADR-0014）。

### §5.4 绝对禁止强行对应的清单

以下对应**一律不得作为考点或教学内容**（可作为反面案例教学："为什么这种对应是错的"）：

| 禁止对应 | 为什么错 | 档 |
|---|---|---|
| 五行 ↔ 希腊四元素（**作为理论等价**） | 分类逻辑不同：五行有生克闭环与动态转化，四元素无同类循环作用结构。**R1 已补强：①无传播证据（检索性"未找到"，置信度中）②结构差异确认（置信度中–高）③明末《乾坤体义》传入亚里士多德四元行为史实（置信度高）**。→ V0.2 §5.9：禁止"理论等价"成立，但**可另设历史比较课**（明末四元行与五行的调和尝试） | 档 3（等价表述）/ 历史课另计 |
| 12 地支 ↔ 黄道 12 星座（**按序数等同**：子＝白羊…） | 数字相同不构成对应；划分逻辑与含义系统无关。**R1 已细化（V0.2 §5.9 拆成两条）：序数式等同无依据 → 禁止；但星命术以十二地支作宫名且为非序数对应（《张果星宗》「子宫：水清宝瓶」、戌宫＝白羊，置信度中–高）→ 是真实传统用法，可教** | 档 3（序数式）/ 档 1（宫名用法） |
| 八卦 ↔ 行星/塔罗数字牌 | 符号系统各自独立，无历史关联。**R1 确认保持禁止**（刘子华《八卦宇宙论与现代天文》曾被指伪科学并引发 2006 年诉讼，属公开争议） | 档 3 |
| 阴阳 ↔ 塔罗正逆位 | **形似神异**：逆位不是"阴"，逆位是解读约定/程度变化，与阴阳的互补生成逻辑无关 | 档 3（作为考点）/ 可作反面案例 |
| 六亲 ↔ 塔罗宫廷牌 | 功能相似（都指"人/关系"）但**无来源关系**。R1：未找到任何学术或可靠文献 | **档 3 禁止入库** |
| 十神 ↔ 占星相位 | 同为"关系类别"但生成机制完全不同。R1：未找到任何学术或可靠文献 | **档 3 禁止入库** |
| 宫位 ↔ 六爻爻位 | 都是"位置"，但一个基于空间/生活领域，一个基于位阶/时位 | 档 3 |
| 任何"数字相同即对应" | 分类学上的经典谬误：类目数相同 ≠ 结构同构 | 档 3 |

**通用判据（写进内容审核规范）：**
1. **数字相同**不构成对应。
2. **分类逻辑不同**（有无循环作用、有无生成关系）不得对应。
3. **形似而机制不同**（如逆位 vs 阴阳）必须明确区分，并可作为教学重点。
4. **跨 Formalism 的关系一律走边**：有争议、来源不明 → 标注"类比"且不进考点；**找不到任何可引证来源 → 档 3，禁止入库**（ADR-0011 + R1）。
5. **R1 的元教训（V0.2 §5.9）：** AI 的"常识"在术数史领域**两个方向都会错**——既可能过度宽容（把附会当理论），也可能过度禁止（把真实的传统用法当附会，如十二地支作宫名）。**凡涉及具体对应关系，必须走带来源的外部核查，且核查本身也要进审核队列。**

## §6 从 0 到第一门术数的阶段

**关键设计：阶段之间由 Mastery 向量阈值判定，不由"课程完成度"判定。** 否则会教出"通关了但不会用"的用户。

| 阶段 | 名称 | 用户能做到 | 对应等级 | 主要题型 |
|---|---|---|---|---|
| 0 | **象数素养** | 操作 S1–S4：指认、归类、配对、判断有向作用 | 前置 | 识别、匹配、分类、关系判断 |
| 1 | **符号识字** | 认全本体系的符号集，说出核心属性 | A1 | 识别、匹配 |
| 2 | **属性与关系** | 说出符号间的体系内关系，并说明依据 | A2 | 分类、比较、关系判断 |
| 3 | **单点判断** | 在给定条件下做出单个判断（如某爻旺衰） | B1 | 推理、结构分析（小） |
| 4 | **结构分析** | 读完整结构（牌阵/卦/星盘），指出关键点与次要点 | B2 | 结构分析、推理 |
| 5 | **综合解读** | 组合多因素形成解读，并区分"所示"与"推测" | C1 | 开放式解读 + Rubric |
| 6 | **独立实战** | 按过程规范完成一次完整咨询式解读（含伦理动作） | C2 | 实战关卡 + 过程 Rubric |

**注意：**
- 阶段 0 是**体系无关**的，且**跨体系复用的正是这一层**。已掌握体系 B2 的用户进入体系 A，仍需过阶段 1–2，但阶段 0 可直接豁免测试。
- 阶段 6 的考核对象是**过程规范**（ADR-0004），不是准确率。

## §7 一门术数如何形成技能树

### §7.1 技能树的生成方法（不靠灵感，靠图）

```
1. 列出体系全部 Symbol           → 得到"要认的字"
2. 抽出体系全部 Relation + Rule  → 得到"要会的操作"
3. 把操作按 Schema(S1–S9) 归类   → 得到能力族
4. 每个能力族写出 Skill（动词+对象+条件）
5. 用 prerequisite_of 连成 DAG
6. 用 projects_to / transfers_as 挂到 Concept 与 Schema 上
7. 由 DAG 线性化 + 认知负荷排序 → 得到 Curriculum（这是 Path，不是 Skill 本身）
```

**Skill 的书写规范：** `能在【条件】下，对【对象】执行【操作】，并【说出依据】`
- ✅ "能在给定月建日辰下，判断用神是否受生扶，并说明依据是哪一组生克"
- ❌ "理解用神"（不可评估）
- ❌ "掌握六爻"（不是 Skill，是体系）

### §7.2 塔罗技能树（示例，非最终内容）

按 brief 的塔罗路线，翻译成 Skill DAG：

```
T0 塔罗素养（= 阶段0 迁移复用）
 └─ T1 符号识字：认 78 张牌 + 说出元素/数字/极性
     ├─ T2.1 大阿卡纳：22 张的核心主题 + 相邻牌的序列关系
     ├─ T2.2 四元素：元素属性 → 分组依据 → 元素间互动
     ├─ T2.3 数字系统：数字序列的阶段性含义（1→10）
     │   └─ T3.1 小阿卡纳：元素 × 数字 的组合读取
     ├─ T3.2 牌面象征：图像元素 → 象征 → 多义范围
     └─ T3.3 正逆位：逆位的解读约定（**不是阴阳**）+ 何时不该用逆位
         └─ T4.1 单牌：位置 × 牌义 的条件化解读
             └─ T4.2 两牌关系：支持/削弱/时序/因果（S4）
                 └─ T5.1 三牌叙事：序列结构（S6/S8）
                     └─ T5.2 牌阵：位置含义 → 结构权重（S5）
                         ├─ T5.3 时间线：演化判断（S6）
                         └─ T6.1 复杂牌阵：多子结构整合
                             └─ T6.2 综合解读（C1，Rubric 判分）
                                 └─ T7.1 开放式实战（C2，过程 Rubric + 伦理必修）
```

**与 brief 的差异（需你确认）：**
1. brief 把"正逆位"排在"牌面象征"之后且在"单牌"前——**保留**，但补一条"何时不该使用逆位"（很多现代教学拒绝逆位，这是流派差异，必须标注）。
2. brief 的"四元素"在"大阿卡纳"之后——**保留**，但元素属性属于阶段 2，可提前与 S2/S4 打通。
3. **新增 T0**：基础层与塔罗的桥。否则用户从"完全零基础"进入时无路可走。
4. **新增伦理必修**（T7.1 的前置），对应 ADR-0004 的 scope C。

### §7.3 其他体系技能树

六爻、梅花、占星的技能树在 V0.2 给出。**顺序上有个重要决定：**

> **V0.2 必须先深做塔罗一棵树，再立刻用它去套六爻做压力测试。** 只用一门体系设计的模型必然自洽；两门体系才能证明抽象为真。此时改模型成本最低。

## §8 跨体系学习路径设计

### §8.1 三种路径形态

| 形态 | 触发条件 | 机制 | 可信度 | 优先级 |
|---|---|---|---|---|
| **A. 同源切换** | 用户已掌握东方任一体系 | 复用 Concept 节点，只教新体系的 `Rule` 投影 | 高 | ★★★ 先做 |
| **B. 历史关联** | 塔罗/占星之间 | 呈现有文献记载的对应 + 明确其为后世重构 | 中 | ★★ |
| **C. 迁移类比** | 东西方之间 | `transfers_as` 边 + 类型 4 标注 + 显式"类比"UI | 低（教学有效，理论无依据） | ★ 后做 |

### §8.2 跨体系学习关卡的固定结构

每个迁移关卡必须是**四段式**，缺一不可（这是认识论原则 5 的落地形式）：

```
① 【你已掌握】  用旧体系的概念复述用户已知的结构
② 【新体系中】  展示新体系里对应的结构（并指出不同之处）
③ 【关系声明】  明确标注迁移类型 + 来源强度
                例："二者具有教学上的结构类比（类比，非理论等价）"
④ 【迁移练习】  用旧结构帮助解读新体系的一个具体问题
                + 反向练习：找出一个**类比失效**的场景
```

**第 ④ 段的反向练习是关键设计。** 它防止用户把类比当等价物使用——这正是过度迁移（over-transfer）的防线。例："在六爻里动爻一定引发变卦；在塔罗里没有'动爻'这个机制，牌与牌之间的关系由牌阵定义。请举一个'动爻思维'会误导你的塔罗场景。"

### §8.3 技能树中的标记

跨体系 Skill 在图中用独立样式标记，且其前置必须同时包含：
- 旧体系的相关 Skill（证明已掌握）
- 新体系的基础 Skill（防止跳过阶段 1–2）

**不允许**"已掌握六爻 → 直接解锁塔罗综合解读"。迁移只加速阶段 0，不代替阶段 1–5。

## §9 如何建立用户 Mastery

### §9.1 掌握度是向量，不是百分比

| 维度 | 含义 | 观测方式 |
|---|---|---|
| **识别** Recognize | 见到能认出 | 识别题正确率 |
| **回忆** Recall | 无提示能说出 | 无选项题正确率 |
| **应用** Apply | 给定条件能做判断 | 推理题正确率 |
| **结构** Structure | 能处理完整结构 | 结构分析题 |
| **迁移** Transfer | 能在新体系/新情境复用 | 跨体系题、反向题 |
| **生成** Generate | 能产出自洽且规范的解读 | Rubric 得分 |

外加两个**非能力量**：
- **置信度** confidence：由样本量决定。样本少时掌握度不可信，UI 应显示"数据不足"而不是给一个假数字。
- **衰减** decay：按时间衰减，由 SRS 触发复习（V0.6 定算法）。

**`Tarot / Major Arcana / Fool = 87%` 这种单值表示是错的**，因为它无法区分"记得但不会用"（识别高、应用低）与"会用但会误迁移"（应用高、迁移低）。后者的纠正方式完全不同。

### §9.2 事件模型

```
Attempt(skill_ids[], exercise_id, rubric_hits, correctness,
        hints_used, latency, is_first_try, session_id)
   → Evidence
   → 更新 UserSkillMastery 各维度
   → 更新/新建 ConfusionPair
   → 重排 ReviewItem
```

原则：**掌握度只由 Evidence 更新。** "看完一课""连续签到"不产生掌握度。

### §9.3 混淆对：产品最有价值的学习数据

**内容侧预设（`confusable_with`）：** 教材作者预先声明"这两个东西初学者一定会混"。例：逆位 vs 阴阳、动爻 vs 变卦、相位 vs 宫位、五行水 vs 塔罗水元素。

**用户侧观测（`ConfusionPair`）：** 用户实际把 A 判成 B 的频率与情境。

两者一比，就能区分：

| 情况 | 判断 | 动作 |
|---|---|---|
| 用户混淆了**预设的**混淆对 | 教学正常现象 | 触发设计好的对比练习 |
| 用户混淆了**未预设的**一对 | ⚠️ **内容或教学有问题** | 进入内容质检队列 |
| 用户混淆了**跨体系**的一对 | 过度迁移 | 触发 §8.2 的反向练习 |

> **这是把"错题"从噪声变成产品的核心资产。** 第 2 行尤其重要：它能自动发现课程设计缺陷。

## §10 从练习到游戏关卡

### §10.1 映射关系

```
Skill（能力） → Lesson（关卡） → Exercise（题目） → Rubric（判分）
                                          ↓
                                  Attempt → Mastery → 下一关解锁条件
```

**关卡解锁条件 = Mastery 阈值，不是"答对 N 题"。** 例：

```
关卡 T4.2「两牌关系」解锁条件：
  T3.3 正逆位 · 识别 ≥ 80 且 应用 ≥ 60
  T4.1 单牌   · 识别 ≥ 85
关卡 T4.2 通关条件：
  应用 ≥ 70 且 结构 ≥ 60，且 与"正逆位"相关的混淆对频率 < 20%
```

### §10.2 题型 → 图式 → 能力维度

| 题型 | 测的 Schema | 主要测的维度 | 可否 AI 判分 |
|---|---|---|---|
| 识别 | S1 | 识别 | 规则 |
| 匹配 | S1/S2 | 识别、回忆 | 规则 |
| 分类 | S2 | 回忆、应用 | 规则 |
| 比较 | S3/S4 | 应用、结构 | 规则（+可选 AI 补充） |
| 关系判断 | S4 | 应用 | **规则**（生克/相位由引擎算） |
| 结构分析 | S5 | 结构 | 半规则 + AI |
| 推理 | S5/S6/S7 | 应用、结构 | 半规则 + AI |
| 开放式解读 | S7/S8 | 生成、迁移 | **AI + Rubric**（唯一必须靠 AI 的） |

**注意：** "关系判断"这类题**必须由规则引擎判定**，不能问 AI——AI 可能在生克冲合上产生幻觉，而这是有确定答案的领域（§12）。

### §10.3 游戏化原则（V0.7 细化，此处只定约束）

1. **激励必须挂在"能力增长"上，不能挂在"动作次数"上。** XP 可以由"某维度掌握度提升"触发，而不是"答对一题 +10"。
2. **禁止用简单选择题刷 XP。** 低认知负荷题目权重必须低，否则用户会找到刷分路径。
3. **Streak 不能惩罚休息。** 建议用"学习节奏"而非"连续天数归零"（否则伤害长期留存与学习质量）。
4. **心数/错误次数**只在该关卡内部生效，不跨关卡累积成惩罚。
5. **每周挑战 = 综合运用**（跨 Skill），不是高难度识别题。

## §11 AI 在学习过程中的角色

| 角色 | 具体功能 | 输入 | 输出 | 硬约束 |
|---|---|---|---|---|
| **教师** | 解释概念、答疑 | 用户问题 + 已审核知识片段 | 解释 + **引用知识条目 ID** | 答案必须落在已审核知识范围内；超出范围时明确说"这属于未审核/有争议内容" |
| **陪练** | 出练习、追问 | Skill + 难度 + 用户历史 | 题目候选 / 追问 | 出题进**待审核队列**；不出确定性事实题（那由规则引擎生成） |
| **错误分析器** | 把错误归因到 Concept/Skill | Attempt 记录 | 归因 + 混淆对假设 | 归因结果回写 `Evidence`，供 V0.6 使用 |
| **个性化复习** | 决定今天练什么 | Mastery 向量 + 衰减 + 混淆对 | 复习清单 | **排程算法由规则系统决定**，AI 只生成"为什么今天练这个"的话术 |
| **课程生成辅助** | 起草课程/题目/解释 | 已审核的知识条目 | `draft` 候选 | **永不直接上线**（认识论原则 3） |
| **开放式答案评价** | 按 Rubric 打分 + 反馈 | 用户答案 + Rubric | 结构化评分 + 反馈 | 强制 JSON Schema；按固定反馈结构输出（见 §11.1） |
| **知识关系解释器** | 解释跨体系关系 | 已存在的 `transfers_as` 边 | 解释话术 | **不得自行发明对应关系**；只能解释库里已有的边 |

### §11.1 开放式评价的固定反馈结构

以 brief 的经典案例为例（圣杯六 + 宝剑八 + 圣杯骑士）：

```
用户答："圣杯六表示过去，宝剑八表示被困住，圣杯骑士表示爱情。"

AI 反馈（必须按此结构）：
① 已识别    ✅ 三张牌的核心象征正确（圣杯六：情感记忆；宝剑八：受限；
             圣杯骑士：情感驱动的前行）
② 缺失      ⚠️ 未建立牌间关系。三张牌是并列罗列，没有形成序列结构
③ 倾向性错误 ⚠️ "逐张翻译牌义"模式：把牌当作词，而不是把牌组当作句子
④ 具体修正   宝剑八的"困"通常被理解为认知/自设限制，而非外部强制；
             这会影响整体叙事的方向
⑤ 下一步    → 做一个只练"两牌关系"的短练习（T4.2），暂不进入三牌叙事
⑥ 不做评价   ✗ 不对具体生活事件下判断（不属于学习反馈）
```

**Rubric 示例（T5.1 三牌叙事）：**

| 项 | 内容 |
|---|---|
| `must_hit` | ① 三张牌核心象征正确 ② 说明牌与牌之间的**序列关系**（非并列） ③ 给出**有方向**的整体解读 |
| `should_hit` | ① 区分"牌面所示"与"我的推测" ② 指出宝剑八属认知/自设限制 ③ 说明第三张牌的走向依赖前两张的状态 |
| `forbidden` | ① 逐牌翻译关键词后不作整合（"回忆+困住+爱情"） ② 断言具体事件（"你前任会回来"） ③ 把逆位当阴阳 ④ 体系外推理（用五行解释塔罗） ⑤ 确定性话术（"一定会发生"） |
| `school_variance` | 是否使用固定位置含义；RWS 与托特牌义差异分开处理 |
| `process_rules` | 是否声明所用牌阵与位置定义 |
| `feedback_template` | 见 §11.1 的六段结构 |

> **Rubric 是全项目最难也最值钱的教学资产。** 它同时是：AI 的评测标准、内容质量的检查表、以及产品"不承诺准确率"的法律护栏。

## §12 规则引擎 vs AI 的分工

**总原则：能确定的一律交给规则；只有"没有唯一正确答案"的部分才交给 AI。**

### 规则 / 数据库负责（AI **不得**介入）

| 事项 | 原因 |
|---|---|
| 符号、属性、关系、来源等**全部知识条目** | 事实层，AI 写事实 = 幻觉风险 |
| 生克 / 冲合 / 相位 / 纳甲 / 装卦等**推演** | 有确定答案，可验证 |
| 牌阵/卦象**结构合法性**校验 | 形式规则 |
| 客观题目的**答案与选项生成** | 可穷举校验 |
| 掌握度**计算**与复习**排程** | 需要可复现、可审计 |
| 关卡**解锁条件**判定 | 同上 |
| **任何写回知识库的操作** | 认识论原则 3 |

### AI 负责（规则做不好的部分）

| 事项 | 原因 |
|---|---|
| 开放式解读的**评价与反馈** | 自然语言的"多义但可评估" |
| 对话式**答疑**（限定在已审核知识内） | 需要理解用户表述 |
| 生成**候选**课程/题目/解释 | 提效，但必须人工审核 |
| 错误**归因**与混淆对假设 | 从自由文本推断认知状态 |
| 迁移关系的**解释话术** | 基于已有边，仅做表达 |
| "为什么今天练这个"的**动机话术** | 纯表达 |

### 反幻觉的三道闸门

1. **知识边界**：AI 上下文只注入已审核知识条目；答案必须引用条目 ID。
2. **不得写入**：AI 输出永不直接进 `reviewed`。
3. **落库可审计**：每次 AI 调用记录 prompt / 模型 / 输入 / 输出 / 人工复核标记 → 形成评测集，用于后续校准。

## §13 MVP 应该砍掉什么

**策略（ADR-0003）：纵向切片——穿过全部差异化机制，只做薄薄一层。**

```
MVP = 基础层 S1–S4 + S9（1 个单元）
    + 塔罗 T1–T4.2（指认 → 单牌 → 两牌关系）
    + 1 个跨体系节点 = 塔罗 ↔ 占星（类型 3 历史影响，historicity = 重建，ADR-0014）
    + 1 个开放题（三牌叙事）+ Rubric + AI 反馈
    + Mastery 向量 + 复习排程（简化版）
```

> **跨体系节点的变更（ADR-0014）：** 原定 A（六爻"动爻" ↔ 塔罗"牌组演化"，类型 4，证据低）**已改为 B（塔罗 ↔ 占星，类型 3，`historicity = 重建`，证据中–高）**。理由：①证据强度高一个数量级且有可查文献链（Lévi 1856 → Golden Dawn *Book T* 1888）②所需内容量更小（只需行星/星座名，不需占星课程）③是唯一能同时展示「历史影响 + 近代建构」两种性质的节点 ④第 ④ 段反向练习有 R1 Q1.6 的可查证史实可用（RWS/托特 VIII–XI 次序颠倒），不需自造教学例子。A 留待后续作第二个节点。
>
> **注意：** B 会引入**极少量占星符号**（行星/星座名）作为 ③行星黄道 Formalism 的节点。这不违反「不做占星课程」——**符号可入图谱，课程不做**（V0 非目标清单允许知识图谱留占位节点）。

**这样切的原因：** 它能验证产品最核心的两个命题——"迁移真的帮助学习吗"与"AI 反馈真的能提升解读能力吗"。命题不成立，做再多内容也没用。

| 功能 | 进 MVP？ | 理由 |
|---|---|---|
| 塔罗 T5–T7（牌阵、综合、实战） | ❌ | 依赖 T4.2 的掌握度数据，MVP 拿不到 |
| 六爻 / 梅花 / 占星课程 | ❌ | 一门做深 > 四门做浅。**占星只进符号与一条类型 3 边，不进课程** |
| 跨体系图谱可视化 | ❌ | 需要边足够多才有意义；先做 1 个节点 |
| 完整实战关卡（scope C） | ❌ | **C 是终局目标**；MVP 只做 Rubric 的 `process_rules` 雏形 + 伦理单元草案 |
| AI 对话式导师（自由问答） | ❌ | 先做**受约束的**开放题评价；自由问答的幻觉风险与工程量都高 |
| 成就 / 排行榜 / 社交 | ❌ | 与学习无因果关系 |
| XP / 等级 | ⚠️ | 只做最小闭环；不做数值调优（V0.7 再说） |
| Streak | ⚠️ | 先做"学习节奏"而非连续天数 |
| 间隔重复 SRS | ✅（简化） | 与掌握度同源，早做能早收集数据 |
| 混淆对 | ✅ | 数据资产，越早收集越有价值 |
| 术数图谱页面 | ❌ | 只是导航，不是产品 |
| 管理员内容编辑器 / 审核流水线 | ✅ | **必须有**，否则内容无法维护、无法审核 |
| **规则引擎（含 `RuleTestSet`）** | ⚠️ | MVP 的塔罗几乎用不到，但 **schema 与判分器接口必须现在定义**（M4）；规则引擎本体只做 spike（L2.1 + L6.1），不进用户路径 |
| 多端 / 原生 App | ❌ | Web first |

**"必须有"里最容易被忽略的一项：内容审核后台。** 既然规定"AI 产出一律进待审核队列"，就必须有人工审核界面，否则这条规则会在实践中被绕过。

## §14 内容来源与审核流水线

### 知识条目元数据（所有 Layer 1 实体共有）

```
id, type, canonical_name,
formalism_id?         // Symbol 必有
system_id?, school_id?
sources[]            // 文献/链接；空数组 = 禁止进入 reviewed
source_strength      // 高 / 中 / 低（原名 evidence_strength — ADR-0015⑥）
controversy_flag     // 是否存在流派/学界分歧
controversy_note     // 分歧点与双方立场
transfer_type?       // 仅跨体系边；∈ {3,4,5}（ADR-0011）
historicity?         // 仅 transfer_type = 3
review_status        // draft / reviewed / deprecated
authored_by          // human / ai-candidate
reviewer, reviewed_at, version
```

### 流水线

```
① AI / 人工起草        → draft
② CI 校验              → schema + 引用完整性 + 来源非空 + 跨体系边双标注
                         + judging_mode ↔ AssessmentSpec 绑定（在 Layer 3 校验，ADR-0015⑤）
                         + 派生投影一致性（同一 Formalism 内不得重复建边，ADR-0011）
                         + 禁用语检查（未标注的等价断言 → 构建失败）
③ 人工审核             → reviewed（可上线）
④ 使用中发现问题       → 统一标记 deprecated，不静默删除（保留可追溯性）
⑤ 用户混淆对异常       → 反向进入内容质检队列（§9.3）
```

### CI 校验规则清单（step 1 的验收标准）

| # | 规则 | 依据 |
|---|---|---|
| 1 | `sources[]` 为空 → 失败 | 认识论原则 3 |
| 2 | `transfer_type = 3` 缺 `historicity` → 失败 | §5.2.1 |
| 3 | `transfer_type = 4` 缺配对反向练习 → 失败 | ADR-0007 |
| 4 | `transfer_type ∈ {4,5}` 的内容文本缺「类比」标注 → 失败 | 认识论原则 5 |
| 5 | `judging_mode = 规则判定` 的 Skill，在 Layer 3 无任何 `AssessmentSpec` 绑定 `Rule` → 失败 | V0.2 §1.3 |
| 6 | `judging_mode` 含 Rubric 的 Skill，在 Layer 3 无任何 `AssessmentSpec` 绑定 `Rubric` → 失败 | V0.2 §1.3 |
| 7 | 身为某 System 的 `default_school` 却 `anchor_sources[]` 为空 → 失败 | ADR-0012 |
| 8 | 同一 Formalism 内出现人工 `transfers_as` 边（应为派生投影）→ 失败 | ADR-0011 |
| 9 | 禁用语模式（下表三条）→ 失败 | §14 末 |

### CI 禁用语检查（示例）

构建时对内容文本做模式匹配，命中则失败：

- `五行.{0,6}(等于|就是|=).{0,6}四元素` 等未标注等价断言
- 未带"类比"徽标却使用 `transfers_as` 类型 4 的边
- 出现"一定/必然/百分百/准确率"等确定性话术（§四 伦理边界）

## §16 流派策略（ADR-0006）的架构落地

**决策：** 入门阶段每个体系锁定一个 `default_school`，界面干净、内容不冲突；达到 B2 后解锁「流派对比」课程。

### §16.1 为什么数据模型必须一开始就支持多流派

即使入门只展示一派，内容条目**仍然必须携带 `school_id`**。原因：

1. 同一概念在不同流派的表述不同（六爻用神取法、梅花体用取法）。若入门条目不带流派标记，将来做对比课程时**无法回溯"这条内容到底属于谁"**。
2. 补齐流派标记的成本 = 重写全部内容条目；预留字段的成本 = 0。
3. `controversy_flag` 需要知道"分歧的另一方是谁"，这要求 `School` 实例真实存在。

| 项 | 落地方式 |
|---|---|
| `System` | 新增 `default_school_id` |
| 入门内容查询 | 只查 `school_id = default_school_id` 的条目 |
| 对比课程 | 用 `variant_of` 取同概念的所有流派变体，用 `contradicts` 取冲突声明 |
| UI | 流派徽标常驻（哪怕入门只有一派），让用户从一开始就知道"这是某一派的说法" |

### §16.2 「流派对比」是新的课程形态

它不是"更难的同一门课"，而是**结构性不同的课**：并列多个流派的处理方式，教学目标是"理解分歧点在哪、分歧为何存在"，**不是"记住哪个对"**。

需要新增的支持：

- **新题型**：「同一卦例在两派下结论不同，指出分歧源于哪一步规则」「判断这个断法属于哪一派及其依据」。后者**必须由规则引擎判定**（§12）。
- **Rubric 分支**：对比课的 `school_variance` 从"容许差异"升级为"**考查差异**"，`must_hit` 中必须包含"指出分歧点"。
- **前置条件**：体系 Mastery ≥ B2 且 `识别/应用` 达标。**未达 B2 不得进入**——这正是分阶段策略的意义所在。
