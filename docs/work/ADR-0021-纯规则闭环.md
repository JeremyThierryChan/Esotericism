## 一、这一轮做了什么

把闭环**整条都变成确定性的**，不使用 AI：

```
题目  ← 内容库的关系边（确定性地组合生成）
判分  ← 规则引擎（真值表同样来自内容库）
证据  ← 一次判分产出的观测（含置信度，规则判定 = high）
掌握度 ← 六维向量，样本量决定「数据不足 / 初步 / 稳定」
积分  ← 纯规则函数，且**只挂在掌握度增长上**
```

**为什么这条路让项目更干净：**

| 好处 | 说明 |
|---|---|
| 可复现 | 同一份内容库 → 同一批题、同一判分、同一积分。测试能锁死（已在做） |
| 可解释 | 「为什么这题 0 分」能给出因子明细，不需要猜模型 |
| 无幻觉 | 有唯一答案的地方本来就不该问 AI（V0.1 §12） |
| 不需要服务端 | 整条闭环是纯 TS，浏览器里直接跑 —— 静态站就能完整演示 |
| 内容可规模化 | 题目量来自**关系表的组合**，不需要手写每道题（V0.2 §5.6） |

## 二、题目生成：不产生任何术数知识

`ExerciseTemplate`（Layer 3）+ 确定性生成器：

```json
{
  "rule_id": "rule.wuxing.shengke",
  "parameter_space": { "domain_symbol_ids": ["木","火","土","金","水"], "coverage": "all-ordered-pairs" },
  "prompt_template": "给定两个五行符号「{a}」与「{b}」，判断二者之间的作用关系及其方向。"
}
```

→ 5 个符号 → **25 道题**。

**关键设计：生成器不是真理来源。**

它只做两件事：①在**已存在的**关系边上做有序对组合 ②用**规则引擎**算出答案。
所以内容库里没有的关系，就出不成题 —— 真值表始终只有内容库一个来源。
这一点由测试直接验证：**删掉一条关系边 → 对应题目消失**。

### ⚠️ 一个危险失败模式，以及两道闸门

如果关系表**不完整**，生成器会把「规则查不到关系」当成**「无作用关系」**出成题 ——
那是一个**错误答案**，而且看起来完全正常（有题干、有选项、判分还能通过）。这是最难发现的坏数据。

所以加了两道闸门：

- **CI 规则 R18**（构建期拦截）
- **生成器运行时检查**（运行时也不能绕过）

判定按**无序对**做：关系有方向，但一条边足以回答两个方向的提问（问「火与木」时，
规则会发现存在 `木→火` 的生边，答「b→a 相生」）。
> 这一点我一开始写错了 —— 按有序对判定会误报一半缺失。是测试抓出来的。

## 三、确定性掌握度：样本不足时不给假数字

V0.1 §9.1 的原文要求：「样本少时掌握度不可信，UI 应显示**数据不足**而不是给一个假数字」。
所以这里把门槛写成明确的规则，而不是永远返回一个数：

| 样本数 | 状态 | `display` |
|---|---|---|
| 0–2 | `数据不足` | 字符串 `"数据不足"`（不是数字） |
| 3–9 | `初步` | 数值 |
| 10+ | `稳定` | 数值 |

- 六维向量（识别/回忆/应用/结构/迁移/生成），**未观测的维度不伪造数值**
- 证据按置信度加权：规则判定 `high` = 1.0，AI 判分 `medium` = 0.7，离线骨架 `low` = 0.4
- **不做时间衰减** —— SRS 属 V0.6，现在做了也没有数据校准它
- **只覆盖 `judging_mode = '规则判定'` 的技能**。解释型/生成型需要 Rubric 判分，AI 判分延后（ADR-0020）→ 宁可不给数字，也不给假数字（= 延后清单 D3）

## 四、纯规则积分：把 V0.1 §10.3 的五条约束变成可执行的函数

V0.1 §10.3 的五条是**约束，不是建议**。这里逐条落地：

```
points = 0                                              若未通过，或掌握度没有增长
       = 认知负荷 × 难度 × 新额度 × 重复衰减            否则

认知负荷（原则 2：低认知负荷题目权重必须低）
  识别/匹配 1 · 分类/比较 2 · 关系判断 3 · 结构分析/推理 4 · 开放式解读 5

新额度  novelty = clamp(1 - mastery_before, 0.2, 1)   # 已掌握的内容几乎不给分
重复衰减 repeat = 1 / (1 + 该题历史作答次数)            # 同一题反复答，迅速趋零
```

| V0.1 §10.3 条款 | 落地方式 |
|---|---|
| ① 激励挂在**能力增长**上，不挂在动作次数上 | 掌握度未增长 → **0 分**（闸门 A） |
| ② 禁止用简单选择题刷 XP | 认知负荷权重 1 vs 5；刷 5 道识别题 ≈ 1 道推理题 |
| ③ Streak 不能惩罚休息 | 用「近 7 天有活动的天数」替代连续天数，**中断不清零、无惩罚项** |
| ④ 错误次数只在该关卡内生效 | 不实现跨关卡错误累积 |
| ⑤ 每周挑战 = 综合运用 | 未实现（属 V0.7），但积分函数与题型解耦，接入时不用改公式 |

**反刷分是被测试锁住的，不是被声称的：**
- 重复作答 → 单调不增，最终为 0
- 掌握度到顶后继续答对 → 0 分（真实内容库上的实测）
- 认知负荷：`识别` < `推理`
- 未通过/掌握度下降 → 0 分

**积分账本保留来源**（`attempt_id` / `exercise_id` / `skill_ids` / `at`），可审计。
等级曲线与奖励设计属 V0.7，此处只保证来源可追溯。

## 五、实测结果（真实内容库）

```
内容库 CI 校验：通过（error 0 / warning 0）
生成题目数：25（5 个符号的全有序对）
答案分布：相生 10 · 相克 10 · 无作用关系 5

判分自检：25/25 题「按标准答案作答 → 通过」
判分自检：错误选项被误判为通过次数 = 0（穷举 100 个错项）
```

连续答对 8 题的真实轨迹：前两轮样本不足（按「首次接触」给分），第 3 轮起掌握度可估
（应用维度 = 1.0），**之后继续答对积分归 0** —— 闸门 A 在真实数据上的表现。

测试总数：**156 条**（写作时快照；当前数字见 `pnpm facts`）。

## 六、新增的 CI 规则

| 规则 | 内容 | 为什么 |
|---|---|---|
| **R15** | 模板绑的规则必须存在，且**必须带 `RuleTestSet`** | 规则引擎正确性无从保证，生成的题也就不可信（M6） |
| **R16** | 模板参数空间必须落在规则的 `applies_to_symbol_ids` 内，且符号必须存在 | 防止模板引用已删除的符号 |
| **R17** | 生成的每题必须与「题型↔判分方式」约束一致，且必须有答案键 | 生成路径不能绕过 step 2 定的校验 |
| **R18** | 全组合覆盖时**关系表必须完整**（按无序对判定） | 否则「查不到」被当成「无作用关系」出成错误答案 |

| 没做 | 原因 |

## 八、这一轮之后，「下一步」变清楚了吗

变清楚了一半。**内容重心确定下来**：纯规则判分只能覆盖确定性推演，
因此优先扩**规则密集型**内容（六爻装卦/纳甲/六亲/世应/旺衰、五行生克冲合），
这条路的题目量可以由关系表组合出来，边际成本极低。

**但这条路有一个硬约束必须先解决：规则数据也必须有来源。**
现在唯一的规则数据集（`rule.wuxing.shengke`）是 R1 Q2.2 支撑的；
若要做六爻装卦/纳甲/六亲/世应，需要对应的**可引证文献**（《增删卜易》《卜筮正宗》《易隐》一系），
而 R1 只核实了这些书的**书名与作者归属**，没有核实表格内容。

→ 所以下一步有两条，建议按序：

1. **先做内容复核（T1–T3）**：把五行关系表升到 `reviewed`（核一手文献），
   这是唯一能让内容脱离 `draft`、并让可见性策略可以收紧（D6）的路。
   成本：人工查证，不需要写代码。
2. **再做第二组规则内容**：选一个**文献可核**的确定性程序（建议从「由三爻阴阳定八卦」
   这类**结构性**规则入手 —— 它是二进制组合，不是解释性理论，争议最小），
   按同一模板路径扩题量。

> 若不先做 ①，追加的规则内容也会立刻堆在 `draft` 上，`reviewed` 会越欠越多。
