# ADR-0026 · 内容流水线工具（录入 / 审核 / 试玩预览）

> 状态：**✅ 已实现**（未部署 —— 它是**本机工具**，不上线）
> 依据：ADR-0008「第一个要写的 UI 是内容流水线工具」· 缺口清单 **C2-2**
> 代码：`apps/studio/`（4 个源文件 + 3 个测试文件 + 冒烟脚本）
> 关联：ADR-0025（本工具发现并修掉的 CI 覆盖漏检）

---

## 一、为什么是它，为什么是现在

ADR-0008 写得很早：**第一个要写的 UI 不是学习者端，而是内容流水线工具**（录入 / 审核 / 试玩预览）。

缺口清单的优先级图里，它排在 ③（② 落库已完成）。选它的**决定性理由不是「轮到它了」**，而是：

> 缺口清单里排第 ① 的事是**人工签字（D1）**，而 D1 **只有人能解开**。
> 那 AI 能对 D1 做的唯一有价值的事，就是**把签字这件事的摩擦降到最低**。

签字为什么一直没做？不是不愿意。是 62 条带 provenance 的条目、45 条复核记录、22 条 CI 规则、
外加一份 171 行的 `docs/复核记录-T1-T3.md`，没人能一眼看出：

- 现在到底**哪些条目可以签**？
- 签之前还**差什么**？（R1a 来源？R1b 作者？R19 人工复核？）
- 我核过的东西**记在哪一栏**、写完会不会被 CI 打回？

这个工具就是把这三个问题各做成一屏。

---

## 二、三个功能，以及各自真正的价值

| 功能 | 表面做什么 | 真正的价值 |
|---|---|---|
| **审核工作台** | 列出全部带 provenance 的条目，显示状态与阻塞项，提供「记一条人工复核」与「签字/撤回」 | 让签字**可判断、可执行、可撤销** |
| **录入** | 选集合 → JSON → 校验 → 保存（可从现有条目克隆骨架、可看合法引用清单） | 让改内容**不会写坏内容库**（写前写后都校验，失败自动回滚） |
| **试玩预览** | 显示每个模板能生成多少题、样题与正确答案 | 题目是**生成**的，改一条边会整体变化 —— 得能先看见 |

## 三、四个关键设计决定

### ① 「能不能签字」不自己算 —— 把条目推进**真校验器**

工具**不重新实现任何 CI 规则**。判据是：

```
把条目在内存副本里改成 reviewed → 跑真正的 validateBundle → 看它报什么
```

**为什么必须这样**：任何「工具自己算一遍规则」的实现都会与 `validate/rules.ts` 漂移，
而漂移的表现是**工具说「可以签字」、CI 说「不行」**。这种谎比没有工具更糟 ——
人会对着一个 ✅ 点下去，签的是一个没核过的东西。

`test/inventory.test.ts` 把这条当不变量逐条验：**每一条**「工具说没有阻塞」的条目，
都真的推进校验器确认它不报 error；反之亦然；连**规则号**都要与校验器报的一致。

> 这条不变量不是装饰：**它当天就抓到了 ADR-0025 那个漏检**（见下）。

### ② 工具**只能**写 `checked_by: 'human'`

R1b/R19 拦的是**状态**（AI 起草的不能变 reviewed），拦不住**动作**。
如果工具给一个「记一条 AI 复核记录」的按钮，那从「AI 找到来源」到「条目 reviewed」
就只差一次点击，而点击的人并没有核对原文 —— 闸门会被**合规地**绕过。

所以把入口本身去掉：能进 `verifications[]` 的 AI 记录，只能由作者直接写进 `bundle.json`
（那是有意为之的动作，不是一次误点）。

### ③ 写回的是**原始 JSON**，不是 zod 的输出

这是踩出来的。最初的实现是 `JSON.parse` → `contentSchema.parse` → `stringify(zod 输出)`，
结果**整份文件 974 行 diff**：

- **键序变了**：`entityBaseSchema.extend({...})` 的字段顺序是「base 的键在前」，
  于是 `formalism[0]` 从 `id, name, description, symbol_scope, provenance`
  变成 `id, provenance, name, description, symbol_scope`；
- **默认值被实体化**：`.default([])` 把文件里**没有**的 `verifications: []` 补了出来。

后果不是「丑」而是**危险**：每次签一个字都产生上千行 diff，git 历史失去可读性，
于是没人再看得出这次签字改了什么 —— 而签字本身的意义就是「有人看过」。

**现在**：zod 只用于校验（`safeParse`），写回一律用原始 JSON 对象（`loadBundle` 同时返回
`json` 与 `bundle` 两个视图）。`store.test.ts` 用两条测试锁死这件事：
「未修改的内容库写回去字节不变」+「拿 zod 输出写回会产生 200 行以上 diff（反例）」。

### ④ 写入门：原子 + 校验 + **只看新增 error** 的回滚

- **原子**：临时文件 + `rename`。写到一半被打断不能留下半个 JSON —— 唯一的事实来源坏了没有第二份。
- **写前**校验 schema；**写后**从磁盘读回来再校验一次（真正的事实来源是磁盘上的字节）。
- **只回滚「写入前不存在的」error**：内容库本来可能就带着若干 error 在开发中，
  若一律拒绝写入，工具就完全用不了 —— 那会把「不许写坏」变成「什么都不许做」。

## 四、这个工具当天就抓到了两个缺口

工具要做「哪些能签字」，就必须把 62 条逐条推进校验器。一推就发现：

1. **`exercise` 与 `exercise_template` 完全没被 R1/R19 检查**（两者 schema 都带 `provenance`）——
   题目可以被标成 `reviewed` 而不需要任何人工复核记录。**已修**（ADR-0025）。
2. **`transfer_edges` 结构上无法签字**（没有 `provenance`，只有裸 `sources`）——
   我们唯一那条跨体系迁移边永远停在「有来源但无人复核」。**未修**，登记为 T8（需独立 ADR，会触及 schema）。

> 这正是「工具化」相对于「再写一份清单」的价值：清单会与代码漂移，而工具必须真的跑到那条路径上。

## 五、安全边界（它有权改唯一事实来源，所以要认真）

| 措施 | 为什么 |
|---|---|
| 只绑 `127.0.0.1` | 不监听 `0.0.0.0`，局域网内其他机器连不上 |
| **校验 `Host` 头** | 防 **DNS rebinding**：恶意页面可把域名解析到 127.0.0.1，只绑本机**挡不住** |
| 静态文件走**白名单**（3 个固定文件名） | 不做路径拼接，没有目录穿越面 |
| 不提供写 `ai-candidate` 的接口 | 见 §三② |
| `DLG_BUNDLE` 可改内容库路径 | **测试与演练绝不会碰真实 `bundle.json`**；冒烟脚本最后断言真实文件 sha256 未变 |

> Host 校验那条**差点写成一条假绿灯**：`fetch` 把 `Host` 当禁止修改的头，传了会被忽略，
> 所以用 `fetch` 测它永远通过。冒烟脚本改用**裸 socket** 才发现问题。

## 六、验证

| 层次 | 内容 |
|---|---|
| 单元（41 条） | 序列化字节稳定 · 写入门回滚 · 清点与 CI 的不变量 · 签字/撤回/复核记录 · 「只写 human」 |
| 冒烟（37 项） | 真起服务真发请求：静态资源 · 目录穿越被拒 · **Host 头被拒** · 完整签字往返 · 撤回 · undo · 真实内容库未被改动 |
| 跨包 | 内容库 62 条全部 draft（签字前应当如此）· 人工复核记录 **0** 条 · 可签字 **0** 条 |

> 「可签字 0 条」不是失败，是**现状的忠实反映**：45 条复核记录全是 AI 写的，
> 依 R19 都不构成签字依据。**这正是这个工具要让人看见的事。**

## 七、仍未完成 / 未决

| 项 | 说明 |
|---|---|
| **签字本身** | 工具就绪，**但签字只有人能签**。这一步必须你自己走（缺口清单 D1） |
| **`provenance.version` 的语义** | 文档只写了 `int().positive().default(1)`，**没有定义什么时候该 +1**。本工具**刻意不自增**（凭空赋予语义属于发明规格）。待拍定 |
| **`reviewer` / `reviewed_at` 是否必填** | 工具会写它们，但 R19 不要求。是否升为 reviewed 的硬要件，未决 |
| **无交互自动化测试** | 冒烟覆盖 HTTP 层与启动路径；**点击/表单交互没有自动化覆盖**（缺口 C2-7 仍在），需要人工点一遍 |
| **不做的事** | 不做服务端、不做多用户、不做权限、不做内容版本回滚（**git 就是版本控制**，工具只提供进程内 undo） |
