# 待采集数据（「攒什么数据」的答案）

> 起因：反复说「自用两周攒数据」，但没具体说**攒什么**。这份文档回答它，
> 同时充当**落库（缺口清单 C2-1）的输入规格** —— 不先定采集什么，落库就会建成一个空表。
> 状态：规格（未实现）。当前**零采集**：积分与作答刷新即丢。

---

## 〇、先分清两件事（否则会拿错数据当结论）

ADR-0008 step 4 的验收标准写的是「拿到 **Mastery 向量**与**混淆对数据**」。但必须区分：

| | 自用两周能攒的 | 攒不到的 |
|---|---|---|
| 性质 | **工程校准数据** | **学习效果数据** |
| 例 | 哪个选项设计有问题、哪道题实际要花多久、我的认知负荷权重拍得对不对、我预测的易混对是否真的会混 | 迁移是否真的降低了学习成本、积分是否真的有激励作用、留存如何 |
| 为什么 | 谁玩都能产出这些 —— 它只依赖「作答与时间」，不依赖「不懂」 | **我是开发者**：知道所有答案、知道设计意图、知道机制 A 为什么成立。这是严重的观察者偏差 |

> **一句话：自己玩能校准仪器，不能证明仪器测的东西有意义。**

## 三、预设混淆对 vs 实测混淆对：为什么这是最值钱的一环

V0.1 §9.3 说混淆对是「产品最有价值的学习数据」，价值全在**两者相比**：

```
内容侧预设（confusable_with）  ─┐
                              ├─→ 一比就分出三种情况
用户侧观测（ConfusionPair）    ─┘
```

| 情况 | 判断 | 动作 |
|---|---|---|
| 用户混淆了**预设的**一对 | 教学正常现象 | 触发设计好的对比练习 |
| 用户混淆了**未预设的**一对 | ⚠️ **内容或教学有问题** | 进入内容质检队列 |
| 用户混淆了**跨体系**的一对 | 过度迁移 | 触发反向练习（V0.1 §8.2 第 ④ 段） |

**第 2 行尤其重要：它能自动发现课程设计缺陷。**

而这需要 `preset` 与 `observed` 能 **join**。所以：

```sql
-- 采集时就要把 preset 对上来，否则三种情况分不出来
confusion_pair(from_label, to_label, exercise_id, count, first_seen, last_seen, matched_confusable_with_id?)
```

我刚加入的 4 条 `confusable_with`（八卦镜像对）就是第一批 **preset**：

| 对 | 位编码 | 为什么预测会混 |
|---|---|---|
| 乾 / 坤 | 111 / 000 | 全阳 vs 全阴，唯一的两个「纯」卦 |
| **震 / 艮** | **100 / 001** | **互为镜像**，都只有一阳、位置相反 |
| **巽 / 兑** | **011 / 110** | **互为镜像**，都只有一阴、位置相反 |
| **坎 / 离** | **010 / 101** | **互为镜像**，中爻相反 |

> **这类预测没有文献来源，也不该有。** 它是关于**学习者会犯什么错**的假设，
> 验证方式是**实测**。所以 CI 对它的提示是：
> 「教学假设无文献来源（这是正常的）：验证方式是实测数据，因此它永远不能靠文献升 `reviewed`」。

## 四、拿不到的（如实列出，避免误用）

| 拿不到 | 为什么 |
|---|---|
| **H3：迁移是否降低学习成本** | 需要「有/无迁移提示」**两组用户对比**。单人玩不出来 |
| **积分是否有激励作用 / 留存** | 需要真实用户；且自己玩有严重观察者偏差 |
| **H4：AI 判分稳定性** | AI 判分延后（ADR-0020）→ 需要 50 条人工标注做一致性检验，现在没有判分器 |
| **真实难度曲线** | 出题人知道自己每道题考什么，难度感知失真 |
| **统计显著性** | 97 题 × 2 周 ≈ 200–300 次作答。够看趋势，不够做检验 |

## 五、最小落库规格（输入给 C2-1）

### 表

| 表 | 关键字段 | 说明 |
|---|---|---|
| `attempt` | id · exercise_id · template_id · session_id · answer_raw · chosen_label · correct_label · passed · latency_ms · hints_used · is_first_try · submitted_at | **原始事实，只追加不改** |
| `evidence` | id · attempt_id · skill_id · dimension · observed · confidence · created_at | 掌握度的**唯一输入**（V0.1 §9.2） |
| `mastery_snapshot` | skill_id · dimension · value · samples · status · at | 快照；否则答不出「当时是多少」 |
| `score_entry` | attempt_id · exercise_id · points · factors(json) · at | 含因子明细，可复盘给分是否合理 |
| `confusion_pair` | from_label · to_label · exercise_id · count · first_seen · last_seen · **matched_confusable_with_id** | `matched_*` 是三种情况判断的关键 |
| `confusable_with`（内容侧） | 已有：from_node_id · to_node_id · rationale · expected_direction | 来自内容库，不落用户库 |

### 三条硬约束

1. **`attempt` 只追加** —— 判分结果可重算，但「用户当时选了什么」不可重建。
2. **`evidence` 是掌握度的唯一入口** —— 不能由"看完了""连续签到"产生（V0.1 §9.2）。
3. **`matched_confusable_with_id` 必须在写入时算好** —— 事后 join 需要内容库的版本，而内容库会变。

## 六、两周应该「怎么玩」—— 否则攒不到第 4 类

随便玩两周，能攒到 1/2/3/5/6/7/8，**攒不到遗忘曲线（第 4 类）**。建议按固定间隔：

```
第 1 天   三题组各做一遍（97 题全做，记录首次答对率）
第 2 天   重答昨天错的题
第 4 天   重答全部（第一次间隔重测，间隔 3 天）
第 8 天   重答全部（第二次间隔重测，间隔 7 天）
第 15 天  重答全部（第三次间隔重测，间隔 14 天）
```

这样每题有 4 个时间点的正确率 → **能画出遗忘曲线**，从而校准 V0.6 的 SRS 参数。
只做一次的话，97 题只是 97 个孤立点，无法回答「什么时候该复习」。

## 七、一句话总结

**攒的是两类东西：**
1. **答案之外的原始行为**：选了什么、花了多久、隔多久再答对 —— 这些我都产不出来（我是作者）
2. **我自己拍的那些数值的实测校正**：认知负荷权重、掌握度门槛、积分曲线、易混淆对预测

**不是**「证明这套学习方法有效」。那需要真实用户，而在此之前至少先把仪器校准好。
